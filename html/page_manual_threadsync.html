About

In a multi-thread environment it can happen that different threads try to access the same resource at the same time. When this happens the handled resource can become corrupted which can lead to crashes. Therefore one must protect such resources with different tools so that only one thread at a time can access it. Typically a semaphore stores a "locked" state. If a thread tries to access the semaphore it will either set the state to "locked" or it will wait until the semaphore is unlocked.

Note
Locks should be used to avoid crashes when seldom used resources are accessed and to protect single threaded operations.
Warning
Make sure that a thread releases a lock after it has finished or a deadlock will be the result.

Thread Lock

The most simple way to protect a resource is to use a global thread lock.

  • GeThreadLock(): Locks the global semaphore.
  • GeThreadUnlock(): Unlocks the global semaphore.
Warning
As this blocks all threads it should only be used if really necessary, a local semaphore is a more elegant and efficient solution to parallel thread data access.
// This example secures the access to the internal data using the thread lock.
void UpdateWithThreadLock()
{
GeThreadLock();
this->DoUpdate();
GeThreadUnlock();
}

GeSpinlock

A GeSpinlock is a fast local lock. The calling thread will wait for the lock for high lock/unlock speed.

  • GeSpinlock::GeSpinlock(): GeSpinlock constructor.
  • GeSpinlock::Lock(): Locks the GeSpinlock.
  • GeSpinlock::Unlock(): Unlocks the GeSpinlock.
  • GeSpinlock::AttemptLock(): Returns true if the GeSpinlock could be locked.
  • GeSpinlock::state: The lock state.
// This example secures the access to the internal data using a SpinLock.
void UpdateWithSpinLock()
{
_spinLock.Lock();
this->DoUpdate();
_spinLock.Unlock();
}

GeRWSpinlock

A GeRWSpinlock allows to handle read and write operations differently:

  • Multiple readers can hold the lock at any time.
  • Only one writer can hold the lock at any given time.
  • A writer must block until all readers have released the lock before obtaining the lock for writing.
  • Readers arriving while a writer is waiting to acquire the lock will block until after the writer has obtained and released the lock.

The functions are:

  • GeRWSpinlock::ReadLock(): Locks and waits for reading.
  • GeRWSpinlock::ReadUnlock(): Unlocks for reading.
  • GeRWSpinlock::WriteLock(): Locks and waits for writing.
  • GeRWSpinlock::WriteUnlock(): Unlocks for writing.
  • GeRWSpinlock::AttemptWriteLock(): Attempts and locks if possible.
  • GeRWSpinlock::state: Read-write lock state.
// This example secures the access to the internal data using a GeRWSpinlock.
void UpdateWithGeRWSpinlock()
{
_rwSpinLock.WriteLock();
this->DoUpdate();
_rwSpinLock.WriteUnlock();
}

Semaphore

The Semaphore is a reentrant mutex that allows to lock a thread.

  • Semaphore::Alloc(): Creates a new Semaphore object.
  • Semaphore::Free(): Deletes the given Semaphore object.
  • Semaphore::AttemptLock(): Returns true if the Semaphore could be locked.
  • Semaphore::Lock(): Locks the Semaphore.
  • Semaphore::Unlock(): Unlocks the Semaphore.
// This example secures the access to the internal data using a Semaphore.
private:
AutoAlloc<Semaphore> _semaphore;
public:
void UpdateWithSemaphore()
{
if (!_semaphore)
return;
_semaphore->Lock((BaseThread*)nullptr);
this->DoUpdate();
_semaphore->Unlock();
}

AutoLocker

AutoLocker can be used to handle the thread-safe access based on the current scope. An AutoLock object is created and given to an AutoLocker in the protected scope. When this scope is left the AutoLocker instance is deleted and the lock automatically unlocked.

  • AutoLock::AutoLock(): AutoLock constructor.
  • AutoLocker::AutoLocker(): AutoLocker constructor.
  • AutoLocker::DoLock(): Locks the given AutoLock.
  • AutoLocker::Unlock(): Unlocks the given AutoLock.
// This example secures the access to the internal data using an AutoLock.
private:
mutable AutoLock _autoLock;
public:
void UpdateWithAutoLock()
{
AutoLocker al(_autoLock);
this->DoUpdate();
}

GeSignal

A GeSignal is a tool for efficient thread synchronization. It is used to keep a thread sleeping and to wake it up. Using GeSignal is more efficient that using a loop with GeSleep().

  • GeSignal::Alloc(): Creates a new GeSignal object.
  • GeSignal::Free(): Deletes the given GeSignal.
  • GeSignal::Init(): Initiates the GeSignal.
  • GeSignal::Set(): Sets the signal.
  • GeSignal::Clear(): Clears the signal.
  • GeSignal::Wait(): Will return true when the signal is set.
// This example implements the "Main" function of a custom C4DThread based thread.
// It is checked if the signal was set.
// The signal can be set from the outside with the thread's DoSomething() function.
void DoSomething()
{
if (!_signal)
return;
_signal->Set();
}
void Main()
{
// prepare GeSignal
_signal = GeSignal::Alloc();
if (!_signal)
return;
// check if GeSignal can be initialized
if (!_signal->Init())
return;
// loop
while (true)
{
// check if the thread should end
if (this->TestBreak())
break;
// sleep for 100 milliseconds
// if the signal is set, "Wait" will return false and the code will be executed
while (!_signal->Wait(100))
{
GePrint("Thread is doing something!");
}
}
// delete the signal
GeSignal::Free(_signal);
}

This document describes how the plugin hooks work and how to register a plugin.

Hooks

All plugin hooks are built upon data classes derived from BaseData. These data classes contain a set of virtual functions that are called by Cinema 4D.

An example from MessageData:

class MessageData : public BaseData
{
public:
virtual Int32 GetTimer(void);
virtual Bool CoreMessage(Int32 id, const BaseContainer& bc);
};

To create a plugin simply derive a class from one of the data classes and override the virtual functions:

class SampleData : public MessageData
{
virtual Bool CoreMessage(Int32 id, const BaseContainer& bc)
{
// ...
}
};

Registration

To register the derived class with Cinema 4D there is a specific Register*() function for each data class. Most of them want an instance of the derived data class:

RegisterCommandPlugin(ID_SAMPLE, name, 0, "icon.tif", "Sample", NewObj(SampleData));

The registration functions for NodeData descendants instead want a function pointer to an Alloc() function like this:

class SampleData : public VideoPostData
{
public:
static NodeData *Alloc(void) { return NewObj(SampleData); }
virtual Int32 Execute(PluginVideoPost *node, VideoPostStruct *vps);
// ...
};
RegisterVideoPostPlugin(ID_SAMPLE, name, 0, SampleData::Alloc, "", 0);

Lifetime

There are a few things to say about the lifetime of the data class instances, especially with concern to member variables. In those cases where an allocated instance is passed to the registration function, as shown in the first example above, then this instance is kept for the whole Cinema 4D session. Since it is constructor and destructor are called as usual, no special concern is necessary.

The data classes that pass an Alloc() pointer to the registration function have a 1:1 correspondence with a node within Cinema 4D. Thus they are allocated and deleted by Cinema 4D along with the node. When this happens the default constructor and the destructor are called as usual. However, Cinema 4D additionally calls the NodeData::Init() function after the constructor and NodeData::Free() before the destructor.

When copying the data class Cinema 4D calls NodeData::CopyTo(), so no copy constructor is used. In addition NodeData::Read() and NodeData::Write() are called when reading or writing the class to the disk.

This means that if there are member variables in the data class, implement at least CopyTo(), Read() and Write().

This is a simple example:

class SampleData : public TagData
{
public:
String myString;
// ...
virtual Bool Init(GeListNode *node) { myString = "Hello World!"; }
virtual void Free(GeListNode *node) {}
virtual Bool Read(GeListNode *node, HyperFile *hf, Int32 level)
{
if (level >= 0) hf->ReadString(&myString);
return true;
}
virtual Bool Write(GeListNode *node, HyperFile *hf)
{
return hf->WriteString(myString);
}
virtual Bool CopyTo(NodeData *dest, GeListNode *snode, GeListNode *dnode, Int32 flags, AliasTrans *trn)
{
dest->myString = myString;
}
};
Note
Often it is much easier to place an item in the node's BaseContainer instead. Then it is not needed to use these functions.

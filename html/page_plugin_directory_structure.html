Plugin Directory Structure

The standard layout for a plugin folder is like this:

  • myPlugin/
  • myPlugin.cdl64 // Windows
  • myPlugin.dylib // OSX
  • ...
  • res/
    • c4d_symbols.h
    • description/
    • myDescription.h
    • myDescription.res
    • ...
    • dialogs/
    • myDialog.res
    • ...
    • strings_us/
    • c4d_strings.str
    • description/
    • myDescription.str
    • ...
    • dialogs/
    • myDialog.str
    • ...
    • strings_de/
    • strings_jp/
    • ...
    • myIcon.tif
    • myWhatever.any
    • ...

The main file is myPlugin.cdl64/dylib, which is the compiled dynamic library file. The res directory contains plugin resources: descriptions, dialogs and strings.

Note
In principal the myPlugin.cdl64/dylib may be located in a subdirectory as well. Just be aware that certain subdirectories won't be searched for plugins.
These are: coffee, res, resource, source, obj, build, api, every directory beginning with strings_ or _api and every directory ending on xcodeproj.

For each description there is a .res with the description and a .h file with enums for the constants used in the description. See Description Resource for the syntax.

Each dialog resource is contained in its own .res file. See Dialog Resource for the syntax.
All constants used in the dialog .res files must be defined as enums in the c4d_symbols.h file (see below).

Then there should be a directory named strings_XX for each language that the plugin supports, where XX is a 2-letter language or country code according to the ISO 3166-1 standard.
Currently there are Cinema 4D versions available for the following codes:

  • us - American English
  • de - German
  • fr - French
  • it - Italian
  • jp - Japanese
  • es - Spanish

Each of the language directories should contain a .str file for every dialog/description and a c4d_strings.str for other resource strings. It is recommended to first develop the plugin in one language, and then just copy the strings directory before translating.

The c4d_symbols.h file, with the constants from dialogs and the general string table, can be included into the plugin code, as can each description's .h file. Cinema 4D parses these files when loading resources.

Finally it is possible of course to have any other files in a plugins folder, for example plugin icons or logos. These can be conveniently accessed using GeGetPluginPath().

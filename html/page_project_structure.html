This document explains how the SDK project is setup, focusing on the changes between the R15 and R16 SDK project structure and settings.

Normally you do not need to know this, since you can just use the example SDK project as a basis for your own plugins. However, if your project structure is complicated, knowing these differences could make it easier to port your project from R15 to R16.

General

  • New include paths must be set. Instead of the list of several directories under "..\..\resource\_api", now those directories are under "..\..\..\frameworks\cinema.framework\source".

Visual Studio

  • The compiler options for Pointer-to-member representation must be set to "General-Purpose Always" and "Point to Single-Inheritance Classes" in C++ tab/C++ language (/vmg /vms). If not set, the plugin will crash instantly!
  • "Enable Exception handling" in C++ tab/C++ language can be disabled to reduce code size.
  • If the plugin is not directly placed in Cinema 4D's plugin folder, the relative paths need to be adapted: e.g. "..\..\resource" becomes "..\..\..\resource" (to go one level deeper).
  • The RootNamespace defined as "cinema4dsdk" has been redefined to "maxon".
  • The CharacterSet value is now set to Unicode.
  • WholeProgramOptimization is now set to true for Release targets.
  • The user macro C4D_API_PATH defined as "../../resource" was replaced with MAXON_ROOTDIR defined as "..\..\..".
  • The Project value _api defined as "..\..\resource\_api_lib\_api.vcxproj" was replaced with cinema.framework defined as "..\..\..\frameworks\cinema.framework\project\cinema.framework.vcxproj".
  • The ProjectReference Include value defined as "..\..\resource\_api_lib\_api.vcxproj" is now defined as "$(MAXON_ROOTDIR)\frameworks\cinema.framework\project\cinema.framework.vcxproj".
  • The AdditionalIncludeDirectories value defined as "$(C4D_API_PATH)\modules\sculpt\res\description;" is now defined as "./source;./res;./res/description;".
  • A set of project targets that are prefixed with "Lib" have been added to R16. The framework is built in the Cinema 4D project build and requires these configurations. Keep using the Release and Debug targets to create your plugins. The Intel targets should be ignored, since the Intel compiler is used to produce the final build of Cinema 4D. There is no debug build under Intel.

Windows DLL Dependencies

Put the plugin's DLL dependencies into <Cinema 4D installation directory>/resource/libs/win64 folder. Cinema 4D registers that folder on startup, and when your plugin will be loaded, Cinema 4D will load the DLL dependencies from there.

Mac OS X / XCode

Similar to the changes for Visual Studio, changes must be made to the XCode project file:

Note
Due to extensive differences between the R15 and R16 XCode project files, some changes may not be listed here. Please review the project.pbxproj file to discover all the changes.
  • sourceTree has been redefined from "<group>" to SOURCE_ROOT

The following 2 build settings are defined for both Debug and Release targets, and replace C4D_ROOTDIR and HEADER_SEARCH_PATHS:

  • MAXON_ROOTDIR is defined as "../../../"
  • USER_HEADER_SEARCH_PATHS is defined as "./source ./res ./res/description frameworks/cinema.framework/source/** $(inherited)"
